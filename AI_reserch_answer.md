# Sentry + GitHub/Vercel CI/CD Pipeline Integration Guide (2025)

Complete setup for integrating Sentry error monitoring into your React 19 + Vite 6 application with automated GitHub Actions and Vercel deployment pipeline. This guide covers the latest 2025 best practices for production deployments.

## Pipeline Architecture Overview

**Recommended approach for 2025:** Use Vercel's native Sentry integration for simplicity, with optional GitHub Actions for advanced release management. Source maps upload automatically during Vercel builds.

```
GitHub Push → Vercel Build → Sentry Plugin → Source Maps Upload → Release Creation
     ↓              ↓              ↓               ↓                 ↓
  Triggers      Vite Build     Auto Upload    Delete Maps      Link Commits
```

## 1. Vercel Native Integration Setup (Recommended)

**Use Vercel's built-in Sentry integration instead of manual configuration.** This is the 2025 best practice as it handles environment variables, authentication, and deployment tracking automatically.

### Installation Steps:
1. Go to [Vercel Integrations](https://vercel.com/integrations/sentry)
2. Click "Add Integration" and authorize both accounts
3. Select your Vercel project and link to your Sentry project
4. The integration automatically creates these environment variables:

```bash
# Auto-generated by Vercel Integration
SENTRY_ORG=your-org-slug
SENTRY_PROJECT=your-project-name  
SENTRY_AUTH_TOKEN=sntrys_auto_generated_token
NEXT_PUBLIC_SENTRY_DSN=https://your-dsn@sentry.io/project-id
```

### Benefits of Native Integration:
- Automatic environment variable management
- Secure token handling (rotated automatically)
- Release creation tied to Vercel deployments
- No manual GitHub secrets required
- Handles preview vs production environments automatically

## 2. Vite Configuration for Source Maps

Configure your `vite.config.js` to work with the Vercel integration:

```javascript
// vite.config.js
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { sentryVitePlugin } from '@sentry/vite-plugin';

export default defineConfig({
  plugins: [
    react(),
    // Only include Sentry plugin in production builds
    process.env.NODE_ENV === 'production' && sentryVitePlugin({
      // These are automatically set by Vercel integration
      org: process.env.SENTRY_ORG,
      project: process.env.SENTRY_PROJECT,
      authToken: process.env.SENTRY_AUTH_TOKEN,
      
      // Security: Delete source maps after upload
      sourcemaps: {
        filesToDeleteAfterUpload: ["**/*.map"],
      },
      
      // Link releases to git commits
      release: {
        name: process.env.VERCEL_GIT_COMMIT_SHA,
        setCommits: {
          auto: true,
        },
      },
      
      // Environment-specific configuration
      deploy: {
        env: process.env.VERCEL_ENV || 'development',
      },
    }),
  ].filter(Boolean),
  
  build: {
    sourcemap: true, // Required for Sentry source maps
    rollupOptions: {
      output: {
        sourcemapExcludeSources: true, // Security: exclude source code
      },
    },
  },
});
```

## 3. Environment-Specific Sentry Initialization

Handle different environments (development, preview, production) properly:

```javascript
// src/instrument.js
import * as Sentry from "@sentry/react";

// Only initialize Sentry in Vercel environments
if (process.env.VERCEL) {
  Sentry.init({
    dsn: process.env.NEXT_PUBLIC_SENTRY_DSN,
    
    // Use Vercel's environment detection
    environment: process.env.VERCEL_ENV || 'development',
    
    // Different configurations per environment
    ...(process.env.VERCEL_ENV === 'production' ? {
      // Production: Full monitoring
      sampleRate: 0.5,
      tracesSampleRate: 0.1,
      integrations: [
        Sentry.browserTracingIntegration(),
        // Skip replay in production for free tier
      ],
    } : {
      // Preview: Limited monitoring to save quota
      sampleRate: 0.1,
      tracesSampleRate: 0.05,
      integrations: [
        Sentry.browserTracingIntegration(),
      ],
    }),
    
    // Enhanced release tracking
    release: process.env.VERCEL_GIT_COMMIT_SHA,
    
    beforeSend(event, hint) {
      // Skip development errors
      if (process.env.VERCEL_ENV === 'preview' && event.level === 'info') {
        return null;
      }
      return event;
    },
  });
}
```

## 4. GitHub Actions for Advanced Release Management (Optional)

If you need more control over releases, add GitHub Actions **in addition to** the Vercel integration:

```yaml
# .github/workflows/sentry-release.yml
name: Create Sentry Release

on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  sentry-release:
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0 # Needed for commit history
      
      - name: Wait for Vercel deployment
        uses: patrickedqvist/wait-for-vercel-preview@v1.3.1
        id: vercel-deploy
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
          max_timeout: 300
      
      - name: Create Sentry release
        uses: getsentry/action-release@v3
        env:
          SENTRY_AUTH_TOKEN: ${{ secrets.SENTRY_AUTH_TOKEN }}
          SENTRY_ORG: ${{ secrets.SENTRY_ORG }}
          SENTRY_PROJECT: ${{ secrets.SENTRY_PROJECT }}
        with:
          environment: production
          version: ${{ github.sha }}
          url_prefix: '~/'
          ignore_missing: true
          
      - name: Set release commits
        uses: getsentry/action-release@v3
        env:
          SENTRY_AUTH_TOKEN: ${{ secrets.SENTRY_AUTH_TOKEN }}
          SENTRY_ORG: ${{ secrets.SENTRY_ORG }}
          SENTRY_PROJECT: ${{ secrets.SENTRY_PROJECT }}
        with:
          version: ${{ github.sha }}
          ignore_missing: true
          ignore_empty: true
```

## 5. Secrets Management Strategy

### For Vercel Integration (Recommended):
**No manual secrets needed!** The integration handles everything automatically.

### For GitHub Actions (If Used):
Add these secrets to your GitHub repository (Settings → Secrets and variables → Actions):

```bash
# GitHub Repository Secrets (only if using GitHub Actions)
SENTRY_AUTH_TOKEN=sntrys_your_internal_integration_token
SENTRY_ORG=your-org-slug
SENTRY_PROJECT=your-project-name
```

**Create Internal Integration Token:**
1. Go to Sentry → Settings → Developer Settings → New Internal Integration
2. Name: "GitHub Actions Release Management"
3. Permissions: Project (Admin), Release (Admin), Organization (Read)
4. Copy the token to GitHub secrets

### Vercel Environment Variables:

- **Preview**: Limited tracking to save quota
- **Development**: No tracking (handled by local .env)


## 7. Source Maps Security

Protect your source code while enabling debugging:

```javascript
// vite.config.js security settings
export default defineConfig({
  build: {
    sourcemap: true,
    rollupOptions: {
      output: {
        // Remove source content from maps
        sourcemapExcludeSources: true,
      },
    },
  },
  plugins: [
    sentryVitePlugin({
      sourcemaps: {
        // Delete maps after upload
        filesToDeleteAfterUpload: ["**/*.map"],
        // Don't include source content
        include: ["./dist/**/*.js"],
        ignore: ["node_modules"],
      },
    }),
  ],
});
```

## 8. Preview Deployment Handling

Vercel creates unique URLs for each preview deployment. Handle this properly:

```javascript
// Handle dynamic preview URLs
const getEnvironment = () => {
  if (process.env.VERCEL_ENV === 'production') return 'production';
  if (process.env.VERCEL_ENV === 'preview') return 'staging';
  return 'development';
};

Sentry.init({
  environment: getEnvironment(),
  // Use commit SHA for consistent release tracking
  release: process.env.VERCEL_GIT_COMMIT_SHA,
});
```

## 9. Build Optimization & Performance

Minimize impact on build times:

```javascript
// Conditional Sentry plugin loading
const plugins = [react()];

// Only add Sentry plugin for production builds
if (process.env.NODE_ENV === 'production') {
  plugins.push(sentryVitePlugin({
    silent: true, // Reduce build logs
    debug: false, // Disable debug output
  }));
}

export default defineConfig({
  plugins,
  build: {
    // Only generate source maps in production
    sourcemap: process.env.NODE_ENV === 'production',
  },
});
```

## 11. Common Pitfalls & Solutions

### Issue: Source maps publicly accessible
**Solution:** Use `filesToDeleteAfterUpload` option and `sourcemapExcludeSources: true`

### Issue: Too many preview deploys consuming quota
**Solution:** Use lower sample rates for preview environments:
```javascript
sampleRate: process.env.VERCEL_ENV === 'production' ? 0.5 : 0.1,
```

### Issue: GitHub Actions conflicts with Vercel integration
**Solution:** Use GitHub Actions only for advanced features, let Vercel handle basic releases

### Issue: Environment variables not updating
**Solution:** Redeploy after changing Vercel environment variables
