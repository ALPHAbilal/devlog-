# 📚 PROTOCOL ENFORCEMENT COMMANDS

You now have powerful commands that enforce the rules.md and AI-MEMORY protocols:

## Available Commands:

### `/protocol [task]`
**Full protocol enforcement** - Executes complete checklist from rules.md and AI-MEMORY
- Checks all patterns, current work, and decisions
- Applies Universal Debugging Checklist
- Enforces all rules and documentation

### `/check`
**Quick protocol check** - Rapid scan of AI-MEMORY before starting work
- Fast pattern recognition
- Current context check
- Architecture awareness

### `/debug [error]`
**Debugging protocol** - Full debugging workflow with pattern matching
- Searches known patterns first
- Applies debugging checklist
- Collaborative loop protocol
- Documentation requirements

### `/optimize [component]`
**Performance protocol** - Optimization with mandatory profiling
- Checks performance patterns
- Forces measurement first
- Enforces performance budgets
- Cost-benefit analysis

### `/feature [description]`
**Feature implementation** - New feature with all protocols
- Research and context phase
- Plan-first documentation
- Incremental implementation
- Verification checklist

### `/chain [symptom]`
**Effect Chain Mapping** - Rule 19 protocol for tracing cause-effect chains
- Works backwards from symptom to trigger
- Maps complete chain of events
- Identifies 3 critical points (trigger, decision, mutation)
- Finds optimal fix location (earliest sensible point)

### `/understand [codebase/feature]`
**Elite Code Comprehension** - Rules 21-26 combined for 3-4x faster understanding
- Mental model first (no code for 30 min)
- Backward tracing from outputs (60% more effective)
- T-shaped investigation (broad then deep)
- Time-boxed phases prevent rabbit holes
- Pattern recognition and documentation

### `/archaeology [codebase/module]`
**Code History Deep Dive** - Advanced Rule 26 for understanding WHY code exists
- Identifies problem areas (frequently changed files)
- Finds stable core (old unchanged files)
- Excavates technical debt (TODOs/FIXMEs)
- Evolution timeline analysis
- Identifies domain experts from git history

## How to Use:

1. **Always start with `/check`** for quick context
2. **Use `/protocol` for complex tasks** requiring full enforcement
3. **Use `/debug` for any errors** - it checks patterns first
4. **Use `/optimize` only with measurements** - no guessing
5. **Use `/feature` for new implementations** - ensures proper planning

## Key Files to Remember:

- `/AI-MEMORY/PATTERNS.md` - Known issues and solutions
- `/AI-MEMORY/NOW.md` - Current work tracking
- `/AI-MEMORY/DECISIONS.md` - Architecture rationale
- `/rules.md` - Complete debugging protocols

These commands enforce the wisdom learned from painful debugging sessions and prevent repeated mistakes.
